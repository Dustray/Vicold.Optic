## 修复：两个入口按钮「点得动但看不见」
用户反馈看不出设置/白平衡按钮在哪。真机裁剪放大截图确认：**按钮完全没渲染出来**
（不是显示太淡的问题，是整块被盖）。

根因两层，都不是命中问题：
1. **绘制顺序**：`paintOverlay` 里两个入口按钮画在开头（第 1493-1494 行），
   紧接着第 1497 行画「左侧摄像头避让区」、第 1500 行画左导轨面板、第 1561 行画右导轨 ——
   后画的整块不透明面板把按钮**全部盖死**。
   两侧导轨占位：左 `railLX_=88` 宽 80（x 88..168）、右 `kRailRX=1156` 宽 404（x 1156..1560）。
   原位置恰好全落在其内：设置 x88..168 = 左导轨全宽；曝光 x1366..1546 落在右导轨且压 ISO/SS 滑轨（y138..578）。
2. **底衬太透**：`{1,1,1,0.08}` 白 8% 填充 + `kLine` 淡边，预览画面明暗变化大时随背景消失。

修复：
- 绘制移到 `paintOverlay` **末尾**（快门/AE锁之后），保证浮在最上层。
- 设置按钮迁到 `kSetBtnX=190,Y=44,W=88,H=50`（预览区内，导轨右侧，快变焦圆钮列同一竖列，
  y 44..94 与圆钮列 y180..486 有 86px 间隙，与 HUD 角标行 y16..42 有 2px 间隙）。
- 曝光按钮迁到 `kExpBtnX=1300,Y=56,W=246,H=54`（右导轨顶部空白带 y56..110，滑轨 kTrackY=138 之上，
  仍在快门 kShutterY=318 正上方）。宽度 246 是为容下 5 个字 @fs=16*1.5。
- 底衬改 `{0,0,0,0.80}` + `{1,1,1,0.55}` 描边，字号 16→18（设置）/14→16（曝光），文字统一 kT1。

真机复验：两按钮均清晰可见可点，点击后面板正常打开，曝光按钮选中态橙色高亮正确。

## 修复：快速变焦圆钮列方向与左导轨相反
用户反馈「快速变焦按钮反了，5 在上面，0.7 在下面」。

核查确认：左侧变焦导轨是**长焦在上**（截图实测 2 在上、0.7 在下，专业相机惯例），
而快速变焦圆钮列原为 0.7 在上、5 在下，两者方向相反。

修改：`kQzVals` / `kQzLabels` 数组倒序为 `{5, 2, 1, 0.7}`。绘制（drawQuickZoom）与
命中（quickZoomHit）都按 `i` 递增遍历同一组常量，故只需改这一处。
**竖排列表凡要求「上→下」某顺序时，一律把常量数组倒/正序排，不要在 y 计算里做翻转**
（翻转会漏改命中判定，是这类 bug 的典型来源）。

真机复验：最上档 = `zoom=5.00 az=4.85`（跨带 tele）、最下档 = `zoom=0.70 az=0.77`（uw 带），
命中与显示一致；1x 高亮仍在第 3 档。编译零警告。

## 面板改全屏 + 关闭按钮移到入口位（用户要求）
用户反馈「设置和白平衡里面的内容太紧凑，改成全屏显示，关闭按钮放在入口按钮的位置」。

根因（内容紧凑）：原面板盒 760×~600，控件只有 336 宽 → 8 段白平衡预设**每段仅 42px**，
「暖荧」这种双字标签要塞进 42px，必然挤。

改动（`core/ui/Ui.cpp`）：
- 删掉盒几何常量 `kSetPanelX/Y/W`、`kExpPanelX/Y/W`、`kPanelTopPad`、`kPanelPadB`，
  改为全屏常量：`kPanelPadL=150`（标签左缘）、`kPanelCtlR=1410`、`kPanelCtlW=720`（**每段 90px，
  宽松 2.1 倍**）、`kPanelCtlH=48`、`kPanelHeadH=44`、`kPanelRowH=64`、
  `kPanelTopY=104`/`kPanelBotY=690`（内容区上下界）。
- `buildCtlRects()` 改为按行数算块高并在内容区**垂直居中**
  （设置 3 标题+6 行=516px；曝光 2 标题+3 行=280px，顶对齐会让后者下半屏空着）；
  控件在行内居中 `y+(kPanelRowH-kPanelCtlH)/2`。
- 底色改**全屏实底** `{0.055,0.055,0.065,1.0}`（不再叠半透明压暗，因为面板本身就是全屏）。
- 标签改为**右对齐到控件左侧 24px**（`screenX(c.x-24) - textWidth`），控件右对齐屏边。
- 标题居中（`kStageW/2`），字号 26；分组标题下加一条 alpha 0.10 细线；段间加分隔线。
- **关闭按钮 = 入口图标位**：设置面板左上 `kSetIconX/Y`、曝光面板右上 `kExpIconX/Y`，
  复用同一圆形底衬 + 新增 `closeIcon()`（圆环 + 两根 ±45° 斜条，斜条用 triangles 拼）。
  `handlePanelTap` **第一件事**就是判关闭钮命中（圆形 `hypot <= kIconD/2+kIconHitPad`），
  之后才是控件命中；**取消了原「点面板外关闭」**（面板已全屏，没有"外部"）。

## 近距接管阈值标定（5x 隔一米仍用主摄）

**用户报告**：五倍焦距下即使隔一米还是用主摄；系统相机约 20cm 内才用主摄，超出就用长焦。

**根因（三个叠加 bug）**
1. **阈值是拍脑袋的猜测值**：`enterM=0.9 / exitM=1.4` 比系统相机实测口径宽 4.5 倍。
   1m 内的主体全被判「近距」→ 接管点推到 `teleNearSwitch_=20x` → 5x 永远主摄。
2. **滞回记忆区把状态锁死**：`[0.9, 1.4]` 有 0.5m 宽的「既不进也不退」区（两计数器清零）。
   1m 正好落在里面 → `nearSubject_` 永久卡在 near，出不来。
3. **`near_m=0` 关不掉已锁存状态**：诊断键只改阈值、不清 `nearSubject_`；而状态机条件含
   `nearEnterM_>0`，阈值归零后状态机根本不运行 → 永远退不出（实测 slot 卡在 0）。

**修改**
- `Xiaomi17ProDevice::nearTakeover()`：`enterM 0.9→0.18`、`exitM 1.4→0.30`（对齐系统相机 20cm 口径，
  滞回带收窄到 0.12m）。阈值来源从「猜」变成 focus_d 逐档扫描实测。
- `applyControl` 的 `near_m` 分支：改阈值时若已锁存且（关判定 / 新阈值已大于当前实测距离）
  立即清 `nearSubject_` 并置 `bandDirty_`。
- 新增 `std::atomic<float> lastFdDiopters_`（在 `onFrameResult` 写）：给引擎线程判断
  「当前距离是否已在新阈值之外」。**不能用 `lastFdUi_`** —— 那是回调线程写、UI 路径读的普通 float，
  跨线程直读是数据竞争。

**真机验证（focus_d 逐档 + display slot/crop dbg 观测）**
- 5x @1m → `slot=2 phys=4`（长焦，改前是 slot 0 主摄）✅ 核心问题解决
- 5x @0.17m/0.12m → `subject near` → slot 0（主摄）；回 1m → `subject far` → slot 2 ✅ 双向切换正常
- `near_m=0` 解锁：`near-distance rule cleared (thr=0.00m last=0.12m)` → slot 立即回 2 ✅

**调试踩坑（重要）**
- **`af=1` 与 `focus_d` 不能写在同一个 controls.txt**：每轮轮询全量重放，`af=1` 会把
  `afOn` 重新打开，而 `focus_d` 因值未变不再触发 → 镜头一直自动追焦，读数**卡在 0.47m
  永不跟随**。我据此一度误判「镜头物理下限 0.47m」，实际标称 `minimumFocusDistance`
  是主摄 10 屈光度(0.1m)/长焦 6.67(0.15m)。**测 focus_d 必须只写 focus_d，不带 af**。
- **近距状态机有 12 帧去抖（~0.4s）**：判定已翻转但 `crop dbg` 采样可能早于它，
  看到 slot 没变别急着判失效——延长 sleep 或直接看 `subject near/far` 那条日志。
- **息屏会让相机被 policy 禁用**：启动报 `Camera "0" disabled by policy` 时先
  `dumpsys power | grep mWakefulness`（Dozing/Awake），`input keyevent KEYCODE_WAKEUP` + `keyevent 82` 唤醒。
  不是权限问题，`appops` 怎么 set 都无效。
- **controls.txt 的键是「缺失即保留」**：诊断时用 `near_m=0` 关过判定后，后续只写
  `zoom`/`focus_d` 不会把它恢复回机型默认值（0.18），近距判定一直关着。测完要显式写回阈值。
