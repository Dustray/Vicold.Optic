## 帧率缓降诊断 + MIUI 冻结大坑（14:50-15:15，用户："一直预览帧率慢慢降"→"重新开始"→"再试下"）

  僵尸 task 症状："Warning: Activity not started, its current task has been brought to the
  front" 但 ps 无进程。`-S`/`-W` 先 force-stop → 又触发冻结，禁用。误用不带 --user 的
  install-existing 会装进 user 10（隐私空间）弹权限框卡前台，需 `pm uninstall --user 10` 清理。

## EV/ISO/SS 三向联动（21:50-22:12，用户："如果一个动了，其余的也要跟着动"）
- 确诊 4 个缺口：①混合模式 EV 动→自动侧读数不动（recomputeMixed 结果从不回推 UI，
  onFrameResult 只在 aeOn 时推）；②手动参数动→自动侧不跟随（旧模型=冻结值×2^EV，
  与手动参数无关，亮度漂移）；③自动滚轮指针停旧档位；④controls.txt 的 iso/exp_us/ss/ae
  不同步引擎侧 isoAuto_/ssAuto_ 也不调 recompute（controls 设 iso=400 后下一次 ev 会盖回）。
- **曝光守恒模型**：转混合时刻冻结 AE 乘积 P=iso×exp（∝曝光量）；混合模式自动参数 =
  P/手动参数 × 2^EV —— 手动 ISO 动→SS 反比补（ISO 优先）、手动 SS 动→ISO 反比补
  （快门优先）、EV 动→自动侧整体偏移；EV=0 且手动=冻结值时恰回 AE 解。双自动=HAL AE
  （不变）；全手动=EV 灰显（不变）。lastAe 缺失（冷启动未出 AE 帧）退化单参数基准。
- recomputeMixed 末尾回推 ui_->setAutoIso/setAutoSsUs（自动侧读数即时跟随）；UI 自动侧
  滚轮指针用 nearestStopIdx(autoVal) 派生（log 域最近档，只读不改 isoIdx_）；A 键转手动时
  从当前自动值吸附最近档作为手动起点（值不跳变）。
- controls.txt 新键 `iso_auto=0/1`、`ss_auto=0/1`（与 UI A 键同语义）；顺手修 **ss 键单位
  bug**（原 `1e9/den*1000` 多乘 1000，1/125s 会算成 8s）。
- 真机验证（P=125×8.333ms）：iso=400 → exp=2583230ns 分毫不差；ev=+2EV → ×4=10332920ns；
  exp_us=2000 → iso=512；ss=125 → exp=8000000ns+iso=130；ae=1 → 双自动恢复。截图确认
  自动侧读数（ISO 130 灰字）与滚轮指针跟随。
- **测试方法论坑**：controls.txt 是全量重放语义——追加新键时旧键（如 ae=1）仍在文件里，
  unordered_map 顺序不定，旧行为可能覆盖新值。调试时每步用 `printf ... > $CTL` 整写干净
  文件，不要 `>>` 追加叠加语义冲突的键。
- 已知边界：controls.txt 路径只同步引擎侧 auto 标志，UI 侧 isoAuto_/ssAuto_ 仍由触摸驱动
  （截图里 SS 显示 1/120s 自动读数即此现象）；触摸流程无此问题（拖滚轮时 UI 自己置手动）。
