## 触摸对焦功能审查（只读代码审查，未改代码）
git 基点 929aaaa（触摸对焦 + 三态模式提交后）。审查范围：Ui 触摸链路 + CameraEngine AF 逻辑
+ CaptureSettings 区域编码。结论按严重度：

### P1
1. **区域不随变焦重算**（CameraEngine.cpp:1003 只在此处写 afRegion，全工程无第二处更新）。
   点按时按当时 zoom 换算到 active array，之后拖变焦不再重算。后果：z 变大后区域相对
   可见视场变粗（精度退化），落在画面外时对不在画面的内容测光。
   正解：settings_ 改存 fx/fy（预览归一化），每次 effSettings()/SET_ZOOM 时用当前 zoom 重算；
   区域不必再进 operator!= 的"是否变化"判定（改由 fx/fy+zoom 派生）。
2. **重复点按同一位置 = 死点按**：region 未变 → changed=false 不重发 repeating；policy 0
   又不发 trigger ⇒ 除了动画和触感，相机侧零动作。常见手势（同一处再点要求重扫）落空。
   修法：region 未变但明确是用户再点 → 视为显式重扫请求（直接 sendAfTrigger），
   或缩短兜底窗口。同理 kAfFallbackMs 兜底几乎永不触发：CAF 常态就在 1/2 之间跳，
   afScanned_ 很快为 true ⇒ 兜底条件需复核（建议改为"ROI 回显已生效后 N ms 内焦距无变化"）。
3. **"仅选位置"常驻框让静态覆盖层每帧重烤**：afBoxSticky_ 为真时 afBoxT0_ 永不置 -1，
   Ui.cpp:1256 `if (afBoxT0_ >= 0) markDirty()` + 930 行的 `if (persist) markDirty()` 双重
   置脏 ⇒ 只要选过位置，离屏覆盖层缓存彻底失效（dcc7106 的降频收益归零），持续 GPU/发热。
   修法：把 AF 框挪出静态层（像白闪那样逐帧直画），不再需要 markDirty。

### P2
4. 直方图矩形（x 990..1122 / y 52..118）落在预览区内，点它会画对焦框压住直方图 ——
   应与模式按钮一样做热区排除。
5. **视觉口径与实际不一致**：对焦框 92 设计 px = 预览宽 9.6%，实际下发区域边长 = 宽 15%。
   要么把框画成 144 px（0.15×960），要么区域改 0.096 —— 别一边显示一边不等。
6. **无法回到默认测光**：区域粘滞且无任何复位手势（原有的静态中心框已删除）。
   建议预览区双击/长按 = 清区域回中心评价测光。
7. **跨线程数据竞争**：shotAfterFocus_/shotAfterFocusT0_ 由 glue 线程（fireTapFocus/按钮）
   与引擎线程（setAfState）同读写，非原子。改 std::atomic<int>/atomic<double>，或让引擎
   只置原子标志、由 Ui::frame() 在 glue 线程发 SHOT。
8. FocusShot 可能在 ROI 尚未生效时就拍：result 回显的 AF_REGIONS 还不是新值时 state 已
   合焦。建议门控——只有 `r.afRegions` 回显等于本次下发值之后才允许"合焦"判定/快门。

### P3
9. 静态框删掉后 UI 没有任何真实 AF 模式指示（AF-C / AF-S / MF），手动 focus_d 被点按
   静默取消（onTapFocus 里 afOn=true）用户无从察觉。补一个真实的 AF 模式角标。
10. 多点触摸无 pointer id 区分：双指捏合 = 两次点按对焦。
11. uw 带边界隐患：z<1 时映射到 active array 之外的部分会被钳到阵列边缘（CameraEngine.cpp
    999 行 clamp）。超广角下贴近画面边缘点按的准确性需实测定标。
12. 坐标换算硬依赖"预览流宽高比 == 预览矩形宽高比"（现均为 4:3，device 层改分辨率即静默错位）。

## 自动休眠功能（2026-10-03 晚）
需求：1 分钟无操作自动休眠相机省电降温，预览区提示"已休眠，触摸唤醒"，触摸唤醒。

### 实现（6 文件）
* **CaptureSession::stopRepeating()**：仅 `ACameraCaptureSession_stopRepeating` 不 close
  —— 会话/纹理/输出全保留，唤醒只需重发 repeating（对比重建 ~290ms+纹理失效，瞬启无黑帧）
* **CameraEngine**：`kSleepMs=60000` + `lastInteractionMs_`（run() 启动起算）+
  `sleepCamera()`（stopRepeating + sleeping_=1 + ui setSleeping）/
  `wakeCamera()`（commitSession(true) 重发 repeating + 计时复位防唤醒即入睡）
* **主循环**：休眠触发挂 deviceLost 检查后；**预览看门狗加 `!sleeping_`** ——
  关键坑：停 repeating 后无 result 流入，看门狗会把休眠误判成 stall 自动重发（=白睡）
* **交互刷新点**：drainUiCmds 每条命令、pollControls 有 changed（调试键=用户操作，
  休眠中直接 wakeCamera 把新设置一起下发）
* **Ui**：Cmd 枚举加 `WAKE`；`sleeping_`+`setSleeping/isSleeping`；onDown 顶部的休眠拦截
  （任意触摸只发 WAKE 不执行动作，防唤醒瞬间误触快门/对焦）；frame() 休眠遮罩
  （预览区 0.62 压暗 + 居中"已休眠，触摸唤醒"，30×kUiZoom 字号，逐帧直画不进烘焙层）
* **Gl.cpp 字体 extra 补字**：休眠触摸唤醒，（已 字原有；缺字会静默空白）

### 真机验证（8s 临时值闭环，验证后回 60s 正式装机）
sleep 触发（idle>8s，sleeping=1）→ 遮罩渲染（截图确认压暗+文字）→ 触摸唤醒
（camera wake: repeating resumed，sleeping=0）→ 触摸刷新计时 ✓ 全程零崩溃。
**测试坑**：logcat -c 会把已发生的 camera sleep 日志清掉（app 可能在清日志前已入睡），
验证时勿先清；`crop dbg` 是 UI 帧计数（frame() 每帧打）与相机出帧无关，
不能用它判断预览是否恢复——用 idle dbg sleeping 字段或 camera wake 日志。

### 根因：面板状态变更漏 markDirty（2026-10-03 13:1x 定位修复）
诊断日志证伪了"命中链路有问题"这个方向：
`panel tap: design=(1258,404) panel=2 box=(880,70,632,404) rows=5` →
`panel hit: ctl=(1152,390,336,40) act=10 n=8 -> seg=2` —— **命中与分段全对**。
真正原因：**面板画在逐帧动态层，`applyAwbPreset()` 改完 `awbPreset_` 没调 `markDirty()`**
⇒ 不触发重画，高亮永远停在旧档（`doAction` 里其他 action 每条都调了，就它漏）。
顺带发现 `applyAe`/`applyAwb` 同样漏（靠 onDown 开头的 markDirty 兜住，脆弱）。
另外 `applyAwbPreset` 缺幂等守卫，重复点同一档会重复 pushCmd。

**铁律：任何改变"面板可见状态"的 apply* 方法都必须调 `markDirty()`** ——
面板走动态层（为保住烘焙降频收益），静态层才靠脏重烤。
