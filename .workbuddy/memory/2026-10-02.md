## 触摸对焦"点了不对焦"修复（真机验证通过）
- **根因一（主）**：camera2 metering rectangle 是 **int32×5 (xmin,ymin,xmax,ymax,weight)**，
  左闭右开（NDK 头文件明写）。此前写成 (x,y,w,h,weight) → xmax(614) < xmin(1740) →
  HAL 把矩形钳成**退化点**（回显 [1740 1228 1740 1228] 确诊），统计窗口塌成左上角像素。
- **根因二**：CAF 下改区域未必触发重扫。新增 `CaptureSession::captureTrigger(win, s)`：
  独立单帧请求带 AF_REGIONS + AF_TRIGGER_START（seqId 回收，closeLocked 兜底清理）。
  **trigger 绝不能写在 repeating 上**（camera2 trigger = 每请求实例执行一次 ⇒ 每帧重启扫描永不合焦）。
- **回显诊断**：FrameResult 加 afState/afRegions[5]/aeRegions[5]；引擎点按后 2.5s 加密采窗打
  `af: state=.. region=.. fd=..`（节流 200ms）。afDbgUntilMs_ 驱动。
- **UI 合焦反馈**：对焦框按 CONTROL_AF_STATE 配色（1/3 扫描=橙 kAccent、2/4 合焦=绿
  {74,222,128}、5/6 失败=红、未知=橙）；未合焦时框延长到 6s（kAfBoxHold），合焦后 0.6s
  收尾淡出（afFocusedAt_）。`ui_->setAfState()` 每帧回传。
- **真机证据**：回显与下发逐位一致 [1740 1228 2354 1842 w=1000]；三点三距离
  中心 0.36m / 左上 1.47m / 右下 0.14m = 点哪合哪；扫描 fd 0.1→2.75 连续变化后 PASSIVE_FOCUSED。
- **MIUI 安装坑（新）**：焦点在 user 10（副屏/隐私空间 Launcher）时 adb install 一律
  INSTALL_FAILED_USER_RESTRICTED（确认框在 u0 显示不出来，用户根本没机会点）。
  解法：`am start --user 0 -a MAIN -c HOME` 把主空间切回前台后再装。pm install /sdcard
  不可行（system server 读不到 FUSE），/data/local/tmp 也同样被拦 —— 不是路径问题是焦点问题。
  **MSYS_NO_PATHCONV=1 会破坏 tools/package.sh**（aapt2 收到未转换的 /d/... 路径）——
  打包与 adb 命令分两次跑，别合并。
- 首次点按注入常丢失（am start 后 5s 内的 swipe 不触发 UI）：重发一次即可。

## 触摸对焦"延迟"优化（22:00–22:25，真机测量 + 修复）
端到端时间线用 logcat 时间戳逐段量化，软件侧已压到毫秒级：
1. **抬手才触发 → 按下即触发**：原 onUp 才下发，白白吃掉一个按压时长（80~150ms）。
   预览区无拖拽手势（所有拖拽控件都在各自热区且已 return），不存在误判。
   抽 `Ui::fireTapFocus(x,y)`（pushCmd + 起动画 + tick），onUp 不再处理。
2. **引擎 50ms 轮询 → 命令即时唤醒**：Ui 加 `setCmdNotify()` pushCmd 后出锁回调；
   CameraEngine 主循环 `tickCv_.wait_for(50ms, cmdWake_)`（原 sleep_for(50ms)）。
   实测 tap down → tap focus 同毫秒、trigger +2~5ms。
3. **trigger 请求只挂 1 个 target → 挂全量 targets**（与 repeating 同集合）：CamX 对
   target 集合变化敏感，实测会造成 ~500ms 的结果空档（afc 这个机型尤其敏感）。
4. **CAF full sweep → 单次 AF-S**：CAF+trigger 在本机的行为是「镜头退回无穷远 →
   从 10m 一步步扫到近处」，trigger 到真正起扫 ~1.1s。改 AF_MODE_AUTO + START
   （CaptureSettings::afMode：0=CAF / 1=AUTO），**569ms 拿到 FOCUSED_LOCKED**。
   合焦/失败后保持 2.5s（kAfLockHoldMs）再由主循环切回 CAF —— 立刻切会因 CAF 重评
   再动一次镜头（画面呼吸）。`controls.txt: afs=0` 可退回纯 CAF 行为做对照。
5. **UI 合焦配色准确性**：AF-S 报 FOCUSED_LOCKED 时镜头仍在走向真实合焦点
   （实测 state=4 时 fd 还是旧位置 0.20m，之后 ~1s 才走到 0.61m），直接变绿会误导。
   判据改为「处于合焦态（CAF=PASSIVE_FOCUSED / AF-S 锁定态及其后 INACTIVE 稳定期）
   **且**屈光度连续 3 帧变化 <2%」才向 UI 报 4（绿）。AF-S 锁定后 state 会掉成
   0=INACTIVE（规范正常行为），只认 state==2/4 的话 AF-S 永远不绿 —— 用 afSLocked_ 兜住。
6. **遗留物理限制**：镜头走到最终位置约需 ~1s 量级（VCM + PDAF 扫描），软件侧已无
   压缩空间。af: 诊断日志（state/region 回显/fd 屈光度+米）留在代码里，加密采窗 2.5s。
7. 验证：全程 30fps 无断流、无崩溃，AF-S→CAF 往返正常（back to CAF 日志确认）。
8. **MIUI 安装补充**：焦点跑到 user 10（微信/隐私空间）时安装必失败（确认框在 u0 没
   地方显示）。恢复：把 **u0 自己的 app** 拉前台（`am start --user 0 -n com.vicold.optic/...`）
   比拉 HOME 更可靠（拉 HOME 有时把 u10 的桌面拉起来）。

## "系统相机为什么对焦快"——三策略真机对照（22:30–23:00）
- **端到端分解**：软件链路已 7–10ms（按下即触发+命令即时唤醒），剩余全在 HAL。
  CamX 收到 **AF_TRIGGER 会重启 AF 状态机**：先把镜头甩回无穷远（实测 671ms 后才起扫）
  再从 10m 逐步扫到目标 —— 这就是第三方 App"点了要等一下"的主因。
- **三策略对照**（controls.txt aft=0/1/2；场景=手动 focus_d 推到无穷远再点近距目标）：
  - 0 只换 AF_REGIONS（CAF 常驻不 trigger）：**0.74/0.84s**（最快，默认已改）
  - 1 换区域+CAF trigger：1.57/1.80s
  - 2 换区域+AF-S+trigger（原默认）：1.46/1.68s
  trigger 类慢一倍 = 状态机重启代价。系统相机快的本质：**从不重启状态机**——CAF 一直
  在跑，点按只换统计 ROI（抓系统相机日志实证：点按后 focus_distance 全程恒定 5.484，
  多数时候镜头本就在焦上，无需移动）。
- **假绿 bug（顺手修掉）**：合焦判定只看 [state 合焦态+fd 稳定 3 帧]，点按后头几帧镜头
  未动 fd 天然稳定 → 按下 ~90ms 就变绿（三策略对照全部测出 ~90ms 假绿，判据作废）。
  修复：加第三道 [AF 真的跑过一轮]（state 曾进入 1/3/4/5）或 800ms 超时兜底
  （kAfGreenMinMs，覆盖"点按前本就合焦"的情形）。
- **新默认**：afTapPolicy_=0 + 兜底（kAfFallbackMs=1500 内 HAL 毫无 AF 动作才补一次
  trigger；afScanned_/afFocusLogged_ 双闸保证收敛中绝不打扰）。policy 0 三点三距离
  验证正确收敛（0.95m/0.13m 等）。
- **合焦耗时日志**：`af: FOCUSED steady in Xms (policy=N)` = 点按到 UI 变绿的端到端，
  以后调 AF 直接看这条。
- 遗留物理限制：CamX 起扫延迟 ~600ms + VCM 行程，软件无法消除；policy 0 实测散布
  0.8–1.8s（行程大小主导）。系统相机"秒合焦"的场景多数是"本来就在焦上"。
- 测试坑：**首次注入的 swipe 常丢失**（app 启动/切前台后第一条），重发即可；
  logcat -c 偶发 failed to clear（buffer 忙），用 tail + 时间戳筛选替代。
